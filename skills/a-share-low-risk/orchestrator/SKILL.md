# A股低风险研究 V2 编排 Skill

## 目标
稳定执行一条简单、可审计但不过度结构化的研究链：

`全市场景气发现 → 盈利链拆解 → 公司映射与盈利验证 → 分类估值 → 价格结构 → 机会综合`

本Skill只约束研究顺序和边界，不负责决定哪些行业景气，也不保存任何预设行业答案。

## 三层分工
### Prompt
负责开放式研究判断：
- 哪些行业正在出现盈利边际改善；
- 为什么改善；
- 真正赚钱的是哪条细分盈利链；
- 未来1–2季度是否可能继续；
- 哪些公司真正暴露于该盈利链；
- 最终研究优先级。

### Skill
只负责长期稳定的研究纪律：
- 研究顺序不能漂移；
- 公司证据必须可验证；
- 估值模型必须匹配盈利类型；
- 价格结构不能反向决定内在价值。

### Code
只负责：
- 数据抓取与清洗；
- 全市场机械召回；
- 财务/估值/价格结构计算；
- 数据持久化；
- case-free自洽校验。

代码不得通过固定行业名单、预填signal或简单证据计数决定“哪个行业应该景气”。

## 固定研究顺序
### 0. DATA HEALTH
确认主板范围、最新交易日、行情历史、基础财务数据可用。缺失必须披露，不能解释成“没有机会”。

### 1. OPEN MARKET PROFITABILITY DISCOVERY
由Prompt开放式扫描全部主要行业并横向比较。`config/industry_scan_universe.json`只用于防漏，不是候选答案池。

至少比较：
- 收入与利润变化；
- 毛利率/利润率；
- 产品价格和关键价差；
- 订单、出货、销量、产量；
- 库存、开工率、产能利用率；
- 出口、资本开支、审批/商业化等行业适用领先变量。

输出首先回答：**哪些行业正在变好、改善幅度如何、是在加速还是减速、为什么未来可能继续。**

禁止：
- 先列熟悉股票再倒推行业；
- 只扫描热门行业；
- 读取旧`current_industry_scan_signals`或旧`industry_scan`作为当前答案；
- 因为Registry没有某条产业链就忽略新发现。

### 2. PROFIT CHAIN DECOMPOSITION
只对发现有改善迹象的行业继续向下研究，直到找到能直接解释收入、销量、成本或毛利变化的盈利链。

每条链必须能回答：
`领先变量变化 → 公司经营科目变化 → 利润变化 → 未来1–2季度持续性 → 失效条件`

行业本身不是最终研究单位。例如“化工改善”必须继续拆到制冷剂、氨纶、磷化工、MDI/TDI等真正盈利链；实际拆解结果由当期研究决定，不由Skill预设。

### 3. COMPANY RESEARCH
按`company-research` Skill执行。行业标签只能做映射提示，公司是否真实受益必须回到业务暴露与财务证据。

### 4. VALUATION
按`valuation` Skill执行。先识别盈利类型，再选择模型。Fair Value与低风险买入区分层；同行和历史只作sanity/reference。

### 5. PRICE STRUCTURE
按`price-structure` Skill执行。价格结构独立于价值判断，只回答当前时机是未启动、启动、回踩、趋势延续、过热还是破坏。

### 6. OPPORTUNITY SYNTHESIS
不再维护复杂机会状态机。最终只需回答三件事：
1. 盈利逻辑是否真实且未来1–2季度仍有Bridge；
2. 当前价格相对合理价值是便宜、可接受还是昂贵；
3. 当前价格结构是否适合现在参与。

可输出简洁动作：`观察 / 等启动 / 可分批 / 等回踩 / 不追 / 回避`。

## 研究与机械数据的边界
允许长期保留的GitHub机械资产包括：
- 全市场盈利异常召回；
- 公司行业映射/索引；
- 最新行情与历史OHLCV；
- 全市场价格结构扫描。

Prompt研究结论应集中写入`data/research/v2/research_state.json`，而不是分散成多层预填Driver、锚投票和预期差状态文件。

## Shadow纪律
当前Manifest为Shadow。新架构完成连续验证前，所有结果都必须明确标注：**V2影子研究，不发布正式买点**。
